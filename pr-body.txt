### What changed

Extracted `buildCronUpdatePayload(updates)` from the cron PUT handler's 11-branch conditional ladder + inline schedule parse + repeat normalize (~26 lines) into a single pure helper in `src/lib/cron-field-updates.ts`.

### Refactor 2 — `parseEnvLine(line): EnvLine` helper

The `.env` preview loop in `src/app/config/[section]/page.tsx` (the `sensitive: true` branch of the file editor) had a 4-branch inline parser with 2 string-regex operations. Extracted to `src/lib/env-line.ts` (47 LOC) as a 25-line discriminated-union helper.

```ts
type EnvLine =
  | { kind: "blank" }
  | { kind: "comment"; raw: string }
  | { kind: "invalid"; raw: string }
  | { kind: "keyval"; key: string; value: string };
```

**11 new unit tests** in `tests/unit/env-line.test.ts` cover: blank (empty + whitespace), comment (with/without leading whitespace), invalid (no `=`), keyval (simple, whitespace-padded, empty value, embedded `=`, leading-whitespace-before-`=`), and quote-stripping (single + double quotes, matching python-dotenv behaviour).

**Rule-of-Three exception applied:** helper has 1 call site (the page). Justification is **testability** (3+ conditional branches + 2+ regex ops) per the session-57 pattern. Promotion to `src/lib/` makes it adoptable by a future 2nd callsite without re-promotion.

**Visual fidelity pitfall caught:** the original parser was `line.indexOf("=") + 1` for the value — the helper preserves this exactly, including the behaviour that "  KEY  =value" has key="KEY" and value="  value" pre-trim. A naive "slice around first `=`" would have lost the whitespace-handling semantic. The unit test `treats leading-whitespace before '=' as part of the value` locks this.

### Refactor 3 — `confirmAndRun(message, target, mode, extra?)` helper

The "Restore this agent" inline `if(window.confirm)+void runSeed` block in `src/app/config/seed/page.tsx` (line 184, inside a `.map()` callback) and 4 other `void runSeed(...)` callsites collapsed to a single 4-line helper:

```ts
const confirmAndRun = (
  message: string,
  target: "all" | "root" | "profiles" | "templates" | "categories",
  mode: "merge" | "replace",
  extra?: { slug?: string; templateId?: string },
) => {
  if (message && !window.confirm(message)) return;
  void runSeed(target, mode, extra);
};
```

**5 callsite consolidations:** "Restore Bob only", "Restore this agent" (with confirm), "Restore" (template, in `.map()`), "Restore categories", "Merge missing defaults". All 5 previously had either inline `window.confirm + void runSeed` or bare `void runSeed`. Now they're all `confirmAndRun(message, target, mode, extra?)` calls.

**Outlier kept inline:** the "Restore entire default catalog" button stays in `confirmReseedAll` because its 2-sentence message is too long to inline at the call site. **5/1 ratio doesn't justify a 2-mode helper** per session-51's "two modes max" rule. When the 2nd long-message button appears, extract a `confirmAndRunLong` companion or refactor `confirmReseedAll` to take a message parameter.

**Empty-string sentinel for "no confirm"** avoids a `string | null | undefined` union or a `boolean` flag. The `if (message && !window.confirm(message))` line is the only place the "empty = no confirm" semantic is encoded.

### Refactor 4 — Fix duplicate `requireAuth: jest.fn(() => null)` in `api-routes-complex.test.ts`

The session-38 test-mock-pitfall family flagged duplicate keys in `jest.mock` factories as silent no-ops. This file had exactly that at lines 69-70. Removed the duplicate. Test count unchanged (the duplicate was always silent, no test depended on its presence).

**Audit recipe:** `grep -nE "(\\.mockReturnValue\\(.*\\),\\s*$|\\w+:\\s*jest\\.fn.*,\\s*$)" tests/` — any factory with 2+ identical `mockXxx(...)` lines on adjacent lines is a candidate.
