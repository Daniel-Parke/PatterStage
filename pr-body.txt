**Bug fix — broken `saving` state in ConfigSectionPage:**

The previous session landed half of an intended DRY refactor on
`src/app/config/[section]/page.tsx`: it added a comment claiming
"`saving` is derived as `saveStatus === 'saving'` so the two are never
out of sync", but the `saving` state was *removed* while three
references to `setSaving(...)` / `saving` were left in place:

```ts
// Line 101: setSaving(true);        ← broke (no setter)
// Line 130: setSaving(false);       ← broke (no setter)  
// Line 209: loading={saving}        ← broke (no value)
```

`npx tsc --noEmit` flagged all three as TS2304 errors. The session
*intent* was clearly to derive `saving` from `saveStatus` (matching
the comment), so this session finished the job:

```ts
const [saveStatus, setSaveStatus] = useState<"idle" | "saving" | "saved" | "error">("idle");
const saving = saveStatus === "saving";  // ← derived; one source of truth
```

Net change on this file: -3 setSaving calls, +1 derivation, +0 net LOC.
Build is now clean.

**Consolidation — `fileKeyForFilePath` helper in config-schema.ts:**

// src/lib/config-schema.ts
export function fileKeyForFilePath(filePath: string): string {

Adopted in both file-section branches of ConfigSectionPage
(load and save). Centralises the mapping so the two file sections

don't drift from `behavior-files.ts`' key namespace.

Added `tests/unit/config-schema-file-key.test.ts` with 3 tests
covering `.env → env`, `HERMES.md → hermes`, and the fallback
default for unknown paths.

**Consolidation — `toPatchResponse` helper collapses 6 patch-result switches:**

The previous session (40) extracted `applyProfileOrRootPatch(slug, rootPatch, profilePatch)`
which returns a `ProfileOrRootPatchResult` discriminated union
(`{ok: true, profile}` | `{ok: false, reason: "not-found"}` | `{ok: false, reason: "push-failed", error}`).
This session found that **all 6 call sites** of that helper (and its sibling
`pushProfileOrRoot`) had the exact same 7-line if/else switch that turned
the union's failure cases into a 404 / 500 NextResponse.

Added `toPatchResponse(result, fallbackError)` to `src/lib/apply-profile-or-root-patch.ts`:

```ts
const result = applyProfileOrRootPatch(...);
const err = toPatchResponse(result, "Failed to sync ...");
if (err) return err;
if (!result.ok) throw new Error("unreachable: ...");
```

The unreachable guard is required for TypeScript narrowing — the helper's
return type is independent of the result, so TS can't narrow `result.ok`
from `toPatchResponse`'s signature alone. The throw sits in the hot path
but is never reached in practice (verified by tests).

Migrated call sites:
- `src/app/api/agent/personality/route.ts` (PUT)
- `src/app/api/personalities/route.ts` (POST + PUT shared `upsertPersonality`)
  — preserves the existing 500 log line on push-failed
- `src/app/api/agent/profiles/[id]/toolsets/route.ts` (PUT)
- `src/app/api/skills/[name]/toggle/route.ts` (PUT)
- `src/app/api/agent/files/[key]/route.ts` (PUT — 2 sites: config + non-config branches)

Added `tests/unit/apply-profile-or-root-patch.test.ts` with 4 tests covering
all 4 union shapes (success, not-found, push-failed with error, push-failed
without error fallback).

Net change: -66 / +69 LOC across 6 route/lib files, +53 LOC for the test file.
All 805 tests pass across 156 suites. `npx tsc --noEmit` clean.
