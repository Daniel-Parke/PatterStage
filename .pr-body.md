The `/api/logs` route had a 12-line copy-pasted chain repeated **twice**

```typescript
const safe = sanitizeLogBasename(rawName);
```

**Fix:** Extracted to `injectMissingTimestamps(lines, fallbackTimestamp)`
in `src/lib/log-line-format.ts`. The function delegates timestamp
detection to `parseLogLine().timestamp !== null`, so the two stay in
lockstep — if a new timestamp format is ever added to `parseLogLine`,
the injection helper picks it up automatically. A round-trip test in
the test file asserts this property explicitly.

**Tests:** 5 new in `tests/unit/log-line-format.test.ts` — injects on

Same 7-line `let body: unknown; try { body = await request.json(); } catch { return 400 }` pattern existed across 3 routes after the

tightened the `"content" in body` check using a direct
`"content" in bodyResult && typeof bodyResult.content === "string"`

### 4. `agents/page.tsx` — extracted `agentFileUrl(profileId, fileKey)` helper

`openFile` and `handleSave` both computed the same URL:

```typescript
profileId === "default"
  ? `/api/agent/files/${file.key}`
  : `/api/agent/files/${file.key}?profile=${profileId}`
```

4 lines × 2 sites = 8 lines of duplicate URL-construction. Extracted
to a module-level `agentFileUrl` function (next to the existing
`EditorState` interface). Both call sites are now a single line:
`await apiFetch(agentFileUrl(profileId, file.key))`. If the file API
ever moves to `/api/v2/agent/files/...`, only one place needs updating.

### 5. `personalities/page.tsx` — simplified inline type narrowing for `display.personality`

Was a 3-line triple-guard:


Not a huge win on its own, but the pattern matches what the rest of
the codebase does for optional property checks on `Record<string,
