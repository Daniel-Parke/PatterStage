# Quests

A quest is one small thing worth doing in PatterStage, written as a sentence you
can act on, grouped into a short chain with the others that belong beside it.
"Add a model." "Send your first chat message." "Schedule a mission and watch it
fire." "Take a backup." Together the chains cover the whole product in the order
it is usually learned.

## Where they live

The [Quests](../guides/quests.md) page at `/quests` is the full list: chapters
you can open one at a time, with your progress through each. The rail carries a
counter so you can see there is something left without going looking, and the
dashboard shows the next step rather than the whole board.

## What makes a quest complete

Not a checkbox. Each quest names a thing that happens in the product, and it
completes when the record shows you did it: a mission that reached a terminal
state, a credential that was saved, a backup that wrote a file. It is the same
activity ledger the [Insights](../guides/insights.md) page reads, which means
work you did before you ever opened the quests page already counts.

The first evaluation is quiet on purpose. Everything you have already done is
marked done without a queue of notifications for history.

## They gate nothing

No quest is a prerequisite for anything. Nothing is locked, no feature waits on
a chain, and skipping one costs you nothing but the reminder. They exist because
a control plane with this many screens has a discovery problem, not because
progress needs to be scored. If you would rather not see them, hide the guide
and the pages carry on exactly as before.

Some chains need something your install may not have: a memory server, the
Composer flag, or a host scheduler. Where that is the case the page says so and
names the reason, rather than showing a step you cannot take.

## If you would rather just read

[The first hour](first-hour.md) walks the same ground as the first chapter, in
prose, in one sitting. The [guides](../guides/dashboard.md) cover each screen in
more depth than a quest ever will.
